become a real popup window as originally requested.

1. Create a new route `/cart-popup` that renders a compact, standalone
   cart view (no Navbar, no footer) — reuse the existing cart UI logic
   from `CartDrawer.jsx` but rework it into its own page component
   (e.g. `pages/CartPopup.jsx`), rendered inside its own `CartProvider`.
2. Since cart data already persists to `localStorage` under `dp_cart`
   (see `CartContext.jsx`), the popup works via same-origin
   `localStorage` — no need to pass cart data through the URL.
3. In `Navbar.jsx`, change the cart button's `onCartOpen` handler to call
   `window.open('/cart-popup', 'dp_cart', 'width=380,height=600,resizable=yes')`
   directly inside the click handler (not after any async work, so
   popup blockers don't block it) — instead of opening the on-page drawer.
4. Remove the `<CartDrawer open={cartOpen} onClose={...}>` usage from

   drives it, since it's replaced by the popup route. You can delete
   `CartDrawer.jsx` once `CartPopup.jsx` fully replaces it, or keep it
   unused if you'd rather not risk removing a file — just make sure
   nothing renders it anymore.
5. Make the popup page visibly smaller and denser than the old drawer:
   narrower layout, smaller thumbnails, tighter spacing/padding — sized
   to fit comfortably in a ~380×600 window, not a full-height page.
6. Keep all existing content: item list, qty controls, remove button,
   subtotal, delivery fee, free-delivery hint, grand total, Checkout

7. The Checkout button in the popup should navigate the popup itself to
   `/checkout` (simplest and most reliable — don't try to control the

8. If `window.open` returns null (blocked), show an inline fallback: a

   already reads from `CartContext`, which reads `localStorage`, so

   the browser's `storage` event in the main window's `CartProvider` so
